## Semantics and dispatch

`Engine::register` unconditionally selects `Legacy`; only the private Gantt registration in `with_builtins` selects `NormalizedBuiltin`. A provider cannot opt in by reusing the Gantt ID or model type. The existing `Arc<Registration>` captures the strategy with the module, so later replacement and engine destruction do not retarget retained documents. Other builtin families and public providers retain the original serializer path.

`validate_model_projection` remains before strategy dispatch and executes once. Supported builtin projection calls Serialize once. Exceptional fallback drops its partial Value before calling the unchanged `project_model`; it does not reparse the source, revalidate the model, or invoke render/host callbacks. Gantt's actual serializer and derived task/raw serializers are pure: ordinary maps, sequences/tuples, scalar fields, empty serde_json objects, and a date helper that emits strings/null. No RawValue injection or user serializer is reachable from that captured builtin. The immutable document exposes only a shared model reference, not a public mutation/injection route.

Object construction uses the same `Object::insert` as legacy normalization, preserving first exact-key position and last exact-key value. Existing enumeration and Swift canonical-equivalent-key handling stay downstream. Literal UTF-8 fragments and escape scalars are copied directly; no Foundation decoder/BOM consumption is introduced. Numeric Value creation parses the exact delegated decimal with `str::parse::<f64>`, matching `parse_model_json`; it does not widen f32 before formatting. Quoted numeric/bool keys append to the active string. Nonfinite handling remains the serde_json serializer's decision.

## Formatter coverage and budgets

All 31 Formatter operations in pinned serde_json 1.0.154 were accounted for. The 13 numeric operations are captured through a bounded tee, null/bool/string/escape and structural operations are observed, and RawValue fragments explicitly trigger legacy fallback. The unoverridden `begin_array_value`, `end_array_value`, `end_object_key`, and `end_object_value` use exactly the same defaults as CompactFormatter. Crucially, the default `write_byte_array` invokes methods on `self`, so its array and integer children reach this observer.

Every supported delegated write reaches the count writer before semantic construction. Its all-or-error subtraction check, sticky `exceeded` flag, and 16 MiB boundary match ModelWriter. Numeric capture forwards original chunks first; its 128-byte scratch overflow causes fallback rather than a new public limit. This is adequate for the concrete primitive numbers and does not turn the scratch size into an admission rule.

Depth counts containers, matching the old brace/bracket scan outside quoted strings. At depth 129 the partial tree is dropped, retained frames stop growing, and serialization/counting continues. Only a successful full serialization can report the existing depth message. Writer overflow still outranks a later serializer error; serializer error still outranks depth. The new semantic/depth errors use the same messages and codes, with the existing document wrapper attaching diagram type.

Raw fragments, unsupported state, or incomplete framing fall back to the complete legacy projection; no partially normalized output escapes. The generic-looking formatter is **not** proven equivalent for arbitrary custom serialization. In particular, malformed custom container sequencing after depth suppression is not fully validated by the builder. That is acceptable only because such producers cannot enter this strategy. Do not broaden registration selection without another serializer audit and public evidence.

## Integration coverage and limits

The six proposed tests are public feature integrations, not formatter implementation tests. They compare builtin Gantt against ordinary public registration, including complete normalized values with number-bit equality, ordered object entries, exact legacy envelope bytes, retained rendering, and post-render stability. The frozen construction corpus, empty source, duplicate IDs, missing fields, BOM, combining Unicode, astral characters and escaped controls cover the concrete source-model path.

The budget fixture independently counts the actual model serialization and asserts exact limit−1, limit, and limit+1 sizes. It sequentially drops large models, compares complete errors, and checks successful admission without dumping huge values. At those large accepted boundaries it checks admission rather than complete Value equality; the smaller corpus supplies semantic equality. Keep the exact-size assertions so future model changes cannot silently weaken the fixture.

Provider tests prove Gantt-ID replacements remain legacy and serialize once, including numeric extremes, raw JSON/duplicates, dates, malformed keys, depth and swallowed byte-error precedence. They deliberately **do not exercise optimized** f32/128-bit integer/raw/deep/custom-error/fallback branches. The README accurately makes this distinction. Prepopulated date edge cases are also provider controls, not optimized Gantt coverage. No fallback occurrence or zero-fallback claim has been measured. Avoid presenting these controls as universal formatter validation.

Remaining evidence belongs to the parent: successful compilation, the six targeted integrations and existing module/model contracts, the complete Swift public corpus, and measured allocation plus real Swift parse/first-use results against the frozen 364 control. Profiles should establish that ordinary Gantt enters the new path; an unexpected legacy fallback would undermine the intended experiment even if outputs match. Geometric collection growth and per-fragment bookkeeping may offset removed JSON buffering/scans. No performance, memory, JS parity, or release conclusion follows from this source review.

These observations compare this whole candidate with e148; no difference from a separate e518 measurement is attributed to this layer.

**Passing those regressions does not establish full API parity.** A subsequent direct Pele callback-mutation audit found an existing compatibility bug: the bridge restores callback writes that Pele preserves, reads some fields at different render phases, and rejects a same-owner helper call that Pele permits. The current restoration fixtures mainly compare native transport lanes rather than this mutated oracle contract. That separate feature must be corrected; its audit/architecture work is not included in the measured candidate. Both correctness and performance therefore block release.

Pre-adoption review artifacts retain their historical pending status; the newer local/VM proof records actual completed checks. Original logs and large reports are losslessly compressed with hashes. Big-endian handling, identity-exhaustion01, new03 padding-limit and heavy mixed canonical-limit browser cases remain source-reviewed rather than execution-proven. Packet and compact copy overlap during decoding; smaller payloads establish neither measured process-memory savings nor latency parity. No complete release gate, Intel SDK, AppKit activation or 0.3 release claim.

## Canonical graph and ownership

`publish_entity` preserves the old evaluation sequence: each attribute's key array, comment string, type/name values, provenance-selected property order, attribute record; then the attribute array, style array, entity ID/label/alias/classes, entity record keys, and entity-map key. Moving the ID to a local before constructing the field vector leaves it in the same first-value position. `publish_spec` preserves cardinality/type value evaluation followed by record keys. `finish_initial` preserves root value/key insertion, optional metadata, lookup/claimed fields and the instance node.

The direct builder emits entities in first-declaration order and uses the HashMap only to find already-published ID atoms. It never iterates that map for observable order. The first relationship can create its missing endpoints before publishing the entity Map. Once the Map exists, a new entity causes fallback; this prevents relationship/spec records from preceding a later entity's records. Later bare references to existing entities do not alter any public state. Repeated aliases or nonempty attribute blocks fall back conservatively, including cases whose eventual value might have been unchanged. Class/style/subgraph branches cannot return direct success. Thus a successful direct graph has exactly the empty class/subgraph/lookup/claimed layout emitted by the old adapter for that admitted subset.

Relationship endpoint IDs are the same generated `entity-{name}-{insertion_index}` strings already interned during entity publication. Reusing those atoms removes only guaranteed string-table hits; role and spec insertion order stays unchanged. Empty attributes, self relationships, aliases, numeric-looking names and attribute comment-before-key provenance follow the same shared grammar and publication primitives. Full binary comparison is an appropriate stronger check than comparing visible JSON fields or SVG alone.

The completed state is the same `ErPublicState { graph, model: OnceCell::new() }`. Existing typed/create construction also leaves that cell empty. First render therefore has the same existing graph import/cache operation on both paths, and apply/invoke invalidate it as before. This candidate does not introduce a first-use representation upgrade. The direct header retains no complete entity/relationship mirror; transient attribute blocks and name lookup are dropped with construction.

## Shared grammar and conservative fallback

The `Target for ErModel` adapter preserves the prior sequence of actions. Alias declarations still call add_entity before append_parsed_attributes; bare declarations still use append_parsed_attributes; relationships still ensure both endpoints then invoke the original relationship action; class/style/subgraph operations delegate to their unchanged model methods. Header direction/accessibility metadata and nested-frame bookkeeping remain in the shared reader. The typed path's operation order is unchanged by the Result-returning action interface.

A private fallback flag distinguishes unsupported direct construction from genuine parser errors. Marking fallback immediately unwinds the reader; all provisional graph/token/lookup state drops before the public parse-plan fallback. The public engine then runs its existing typed parse/create exactly once with the same already-prepared context. There is no provider reselection or second preprocessing. A later grammar error after the unsupported declaration is therefore determined by the full legacy parse. A genuine grammar error before fallback is returned unchanged. The final `finish().ok().map(Ok)` also yields to legacy on graph admission failure, instead of publishing a new error precedence.

The public module trait default hook remains None. A provider registered under the ER descriptor does not inherit this optimization unless it explicitly delegates the hook. The test wrapper exercises that isolation. Replacing an engine registration does not retarget an already captured document. Prepared source/adaptation continue through their existing public entrypoints. ER's current typed parser does not enforce a custom numeric edge policy, so the hook's unused edge-limit argument matches the present implementation.
